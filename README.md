## 📌 О проекте

Этот репозиторий — демонстрация подхода к проектированию высоконагруженного чекаута. Здесь собраны артефакты, которые системный аналитик готовит на реальном проекте: сценарии использования, диаграммы взаимодействия, API-контракты и модель данных.

**Ключевые задачи, которые решает система:**
- Оформление заказа с курьерской доставкой и онлайн-оплатой.
- Проверка остатков на складе и расчёт стоимости доставки.
- Резервирование товара на 15 минут при переходе к оплате.
- Умное сплитование заказа на несколько отправлений.
- Асинхронная передача статусов заказа в ERP, аналитику и сервис уведомлений.
- Обработка edge cases: out of stock, payment failed, отмена заказа после оплаты.

## 📐 Артефакты

### 1. Use Cases — [docs/use-cases.md](docs/use-cases.md)

Сценарии оформления заказа:
- **UC-01:** Основной сценарий — успешное оформление заказа.
- **UC-01.A:** Товара не хватило на складе.
- **UC-01.B:** Платёж не прошёл (с ветками «повторить оплату» / «отменить заказ» / «таймаут 15 минут»).
- **UC-01.C:** Отмена заказа после успешной оплаты (с возвратом средств).

### 2. Sequence-диаграмма — [docs/diagrams/sequence-diagram.md](docs/diagrams/sequence-diagram.md)

Взаимодействие Frontend, API Gateway, микросервисов корзины и чекаута, ERP, платёжного шлюза, Kafka и сервиса уведомлений.

![Sequence Diagram](docs/diagrams/sequence-diagram.png)

### 3. API-контракты — [docs/api-contracts.md](docs/api-contracts.md)

| Метод | Endpoint | Назначение |
|-------|----------|------------|
| `POST` | `/api/v1/cart/calculate` | Расчёт корзины с учётом доставки |
| `POST` | `/api/v1/checkout/confirm` | Создание заказа и инициация оплаты |
| `POST` | `/api/v1/payments/webhook` | Webhook от платёжного шлюза |
| `POST` | `/api/v1/checkout/cancel` | Отмена заказа (с возвратом или без) |

### 4. Модель данных — [db/schema.sql](db/schema.sql)

9 таблиц PostgreSQL:
- `products`, `warehouses`, `stock` — каталог и остатки.
- `carts`, `cart_items` — корзина.
- `orders`, `order_items` — заказы.
- `payments` — платежи (с идемпотентностью по `external_id`).
- `deliveries` — доставки.

## 🎯 Ключевые технические решения

| Решение | Обоснование |
|---------|-------------|
| **Kafka для статусов заказа** | Асинхронность, развязка сервисов, устойчивость к пиковым нагрузкам. |
| **Идемпотентность через `order_id`** | Защита от дублей заказов при повторной доставке сообщений. |
| **DLQ для зависших событий** | Обработка ошибок без потери данных. |
| **Резервирование на 15 минут** | Баланс между конверсией и риском «зависших» резервов. |
| **Idempotency-Key в `POST /checkout/confirm`** | Защита от двойного нажатия кнопки «Оплатить». |
| **Webhook от Payment Gateway с проверкой подписи** | Безопасность и защита от поддельных уведомлений. |
